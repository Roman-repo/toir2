# Рабочее место технического специалиста

> Пользовательская инструкция по обработке
> `торо_РабочееМестоТехническогоСпециалиста` (подсистема «Управление нарядами и работами»).

---

## Назначение

**Рабочее место технического специалиста** — единый экран для ведения полного цикла ремонтов и регламентных мероприятий: от выявленного дефекта или планового ППР до закрытия.

Обработка позволяет в одном окне:

- видеть сводный список ремонтов и регламентных мероприятий, подпадающих под заданный период и отборы;
- по каждому ремонту/мероприятию видеть все связанные с ним документы (заявки, наряды, акты);
- создавать документы цикла «одним кликом» с автоматическим вводом на основании;
- массово закрывать заявки и ремонты;
- сохранять личные настройки отбора между сеансами.

Обработка сама не проводит документы и не делает записей в регистрах — это инструмент управления документами. Вся бизнес-логика (расчёты, движения) остаётся в документах.

---

## Как открыть

Обработка доступна в подсистеме **«Управление нарядами и работами»**.

При первом открытии в шапку подставляется организация из общих настроек программы; период по умолчанию — от сегодняшней даты на 10 дней.

---

## Структура экрана

Форма состоит из **шапки** с параметрами периода и отборами и **двух главных вкладок**:

| Вкладка | Что показывает |
|---|---|
| **Ремонты** | Сводный список ремонтов с подчинёнными таблицами заявок, нарядов и актов |
| **Мероприятия** | Список регламентных мероприятий с подчинёнными нарядами и актами |

Под главным списком на каждой вкладке расположены подчинённые таблицы со связанными документами — они обновляются при выборе строки в верхнем списке.

---

## Шаг 1. Настройте отборы

Параметры в шапке формы фильтруют списки ремонтов и мероприятий.

### Период

| Поле | Назначение |
|---|---|
| **Вид даты** | По какой дате фильтровать (плановая/фактическая) |
| **Дата актуальности** | Опорная дата (по умолчанию — текущая) |
| **Плановый период** | Длительность вперёд от опорной даты (по умолчанию 10) |
| **Периодичность** | Единица измерения планового периода: день / неделя / месяц (по умолчанию — день) |

### Прочие отборы шапки

| Поле | Назначение |
|---|---|
| **Организация** | Организация (подставляется из общих настроек) |
| **Исполнитель** | Только ремонты назначенного исполнителя |
| **Подразделение** + **Подчинённые подразделения** | Фильтр по подразделению; при включении флажка подчинённых — вместе с дочерними |
| **Завершённые** | Показывать закрытые ремонты (по умолчанию выключено) |
| **Не проведённые** | Показывать непроведённые документы |
| **Данные по наработке** | Дополнить список информацией о наработке оборудования |

### Расширенные настройки

Кнопка **«Настройки отбора»** открывает отдельную форму, где доступны:

- отборы по **контрагенту**, **договору**, **бригаде**, **подразделению-исполнителю**;
- отбор по **статусу объекта ремонта** (Зарегистрирован → Запланировано → Выполняется → Выполнен) с разделением по источнику — выявленный дефект / внешнее основание / план-график ППР;
- отбор по **статусу документа**;
- **настройка цветов ячеек** по критичности и приоритету объекта ремонта.

---

## Шаг 2. Работа со списком ремонтов

Перейдите на вкладку **«Ремонты»**. В таблице отображаются все ремонты, подпадающие под заданные отборы.

### Что можно делать

- **Выделять строки** — щелчком, с `Ctrl`/`Shift` — несколько подряд или выборочно. Действия применятся ко всем выделенным.
- **Открывать документ двойным щелчком** — открывается выбранный документ (ремонт, заявка, наряд или акт в зависимости от подчинённой таблицы).
- **Смотреть подчинённые документы** — при активизации строки ремонта нижние таблицы показывают связанные с ним заявки, наряды и акты.

### Специальные отборы вкладки «Ремонты»

Эти отборы отображаются только на вкладке ремонтов:

| Поле | Назначение |
|---|---|
| **Остановочные** (флажок) | Показать только остановочные ремонты |
| **Документ остановочного** | Сузить список до конкретного документа остановочного ремонта |
| **Использовать отбор по статусу** + **Статус ОР** | Фильтр по статусу объекта ремонта |
| **Использовать отбор по статусу документа** | Фильтр по статусу самого документа (если включены статусы документов ТОиР) |
| **Группа отборов для адресации** | Дополнительные отборы по адресации заявок |

---

## Шаг 3. Создание документов цикла ремонта

Команды в командной панели создают новые документы **с автоматически подобранным документом-основанием**.

| Команда | Создаёт документ |
|---|---|
| **Добавить заявку** | Заявка на ремонт |
| **Добавить наряд** | Наряд на выполнение ремонтных работ |
| **Добавить акт** | Акт о выполнении этапа работ |
| **Добавить наряд на мероприятие** | Наряд на регламентное мероприятие (на вкладке «Мероприятия») |
| **Добавить акт на мероприятие** | Акт о выполнении регламентного мероприятия (на вкладке «Мероприятия») |

### Как это работает

1. Выделите в списке один или несколько ремонтов (или мероприятий — для регламентных документов).
2. Нажмите нужную кнопку создания документа.
3. Система для каждого выделенного ремонта определяет допустимое основание и автоматически связывает новый документ с ремонтом по `ID`.
4. **Если у ремонта несколько возможных оснований** — откроется форма **«Выбор основания»**, где нужно указать, от какого документа вводится новый.
5. Если основание для какого-то ремонта подобрать нельзя — система предупредит и продолжит создание только для тех, где основание есть.
6. Для ремонтов, происходящих из план-графика ППР, автоматически учитываются корректировки ППР.

Перед созданием выполняются обязательные проверки — если выделенные ремонты не допускают ввода такого документа, операция будет отменена с сообщением.

---

## Шаг 4. Массовое закрытие заявок и ремонтов

Кнопка **«Открыть закрытие заявок и ремонтов»** (становится доступной при выделении строк) передаёт выбранные ремонты в специализированную обработку «Закрытие заявок и ремонтов».

1. Выделите ремонты в списке.
2. Нажмите кнопку.
3. В открывшейся обработке выполните закрытие.
4. После закрытия списки на рабочем месте обновятся автоматически.

---

## Шаг 5. Обновление данных

| Действие | Эффект |
|---|---|
| Кнопка **«Обновить ремонты»** | Принудительно обновляет списки |
| Флажок **Автоматическое обновление** | Списки обновляются сами с заданной периодичностью |
| **Период обновления** | Интервал авт обновления в секундах (по умолчанию 180) |

При создании документа через рабочее место или при закрытии ремонтов списки также обновляются автоматически.

---

## Настройки пользователя

При закрытии формы все выставленные отборы и параметры периода **сохраняются** и **восстанавливаются** при следующем открытии. Пользователю не нужно заново настраивать рабочее место каждый раз.

---

## Типичные сценарии

### Сценарий 1. Обработать выявленные дефекты за смену

1. Установите период на текущую смену, исполнитель — «на себя».
2. На вкладке «Ремонты» отберите по статусу ОР = «Зарегистрирован (выявленный дефект)».
3. По каждому дефекту: выделите ремонт → «Добавить заявку» → заполните → проведите.
4. По мере готовности: выделите заявку → «Добавить наряд» → затем «Добавить акт».
5. В конце смены выделите завершённые ремонты → «Открыть закрытие заявок и ремонтов».

### Сценарий 2. Отработать плановые ремонты из ППР

1. На вкладке «Ремонты» отберите по статусу = «Запланировано выполнение (план-график ППР)».
2. Выделите плановые ремонты на ближайший период.
3. Создавайте наряды и акты по цепочке, при необходимости корректируя основание через форму выбора.

### Сценарий 3. Закрыть прошедшие ремонты

1. Включите флажок «Завершённые».
2. Отберите завершённые ремонты за период.
3. При необходимости — массово закройте через «Открыть закрытие заявок и ремонтов».

---

## Подсказки

- Если списки «пустые» — проверьте период и включён ли флажок **Завершённые** (по умолчанию завершённые скрыты).
- Если кнопки создания недоступны — выделите хотя бы один ремонт в верхнем списке.
- Цвета строк можно настроить в «Настройках отбора» по приоритету и критичности — это помогает визуально выделять срочное.
- Список подчинённых документов обновляется при переходе по строкам верхнего списка — не нужно нажимать «Обновить».
