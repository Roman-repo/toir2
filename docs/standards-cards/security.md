# Карточка: Права доступа и безопасность

> Ключевые стандарты [v8std](https://github.com/zeegin/v8std) по безопасности.
> Полный список раздела — в [`standarts/std/security.md`](../../standarts/std/security.md).

---

## №532 — Установка прав для новых объектов и полей

**Критичность:** 🔴 Блокирующее

**Суть:** Каждый новый объект и новое поле — минимум в одной роли с осмысленными правами. Не оставлять «полный доступ всем» и не оставлять без ролей (объект станет недоступен или, наоборот, открыт). В ТОИР роли — с префиксом `торо_` и осмысленными названиями (Чтение/Добавление/Изменение/Проведение/Пометка удаления).

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/532.md)
См. также: №488 (стандартные роли), №689

## №737 — Проверка прав доступа

**Критичность:** 🔴 Блокирующее

**Суть:** Если в коде есть операция, требующая прав (запись объекта, проведение), и она вызывается не из стандартного интерфейса — проверяйте права явно через `ПравоДоступа(...)` из БСП. Не рассчитывайте, что RLS всё разрешит.

❌ **Неправильно:**
```bsl
// молчаливо выполняем операцию, которая может быть запрещена
Объект.Записать();
```

✅ **Правильно:**
```bsl
Если Не ПравоДоступа("Редактирование", Объект.Метаданные()) Тогда
    ВызватьИсключение НСтр("ru = 'Недостаточно прав для записи объекта'");
КонецЕсли;
Объект.Записать();
```

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/737.md)

## №485 — Использование привилегированного режима

**Критичность:** 🔴 Блокирующее

**Суть:** Привилегированный режим (`УстановитьПривилегированныйРежим(Истина)`) — только для служебных операций (запись в очередь, логирование, обновление ИБ), с обоснованием в комментарии. Не использовать для обхода прав прикладной логики.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/485.md)
См. также: №679

---

## №678 — Безопасность серверного API

**Критичность:** 🔴 Блокирующее

**Суть:** Экспортные функции общих модулей с признаком «Вызов сервера» (HTTP/HTTP-сервисы, общие модули с клиент-серверным вызовом) — это потенциальная точка вторжения. Проверять входные параметры, не доверять данным от клиента, валидировать ссылки.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/678.md)
См. также: №679, №775

---

## №770 — Ограничения на `Выполнить` и `Вычислить` на сервере

**Критичность:** 🔴 Блокирующее

**Суть:** На сервере **не использовать** `Выполнить(...)` и `Вычислить(...)` с данными от пользователя — это инъекция кода. Если без них нельзя — только с полностью контролируемым текстом, без пользовательского ввода.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/770.md)

---

## №740 — Безопасное хранение паролей

**Критичность:** 🔴 Блокирующее

**Суть:** Пароли/секреты — не в коде, не в константах открытым текстом. Через БСП-механизм «Общие настройки» с шифрованием или хранилище паролей.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/740.md)

## №689 — Настройка ролей и прав доступа

**Критичность:** 🟡 Важно

**Суть:** Роли проектируются под бизнес-роли (Бухгалтер, Технолог, Механик). RLS — через схемы БСП. Не создавать отдельную роль под каждое微小 требование — объединять по смыслу.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/689.md)

---

## №488 — Стандартные роли

**Критичность:** 🟡 Важно

**Суть:** Для базовых операций используйте стандартные роли БСП (`БазовыеПрава`, `ЧтениеБазовыхСправочников`, `ПолныеПрава`, `БазовыеПраваВИнтерактивеВсехПодсистем`). Не плодить свои дубликаты базовых ролей. Новые роли — только под уникальные бизнес-группы.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/488.md)

---

## №669 — Ограничение на выполнение внешнего кода

**Критичность:** 🔴 Блокирующее

**Суть:** `Выполнить(...)`, `Вычислить(...)`, внешние обработки/отчёты — выполнять только в безопасном режиме (`БезопасныйРежим = Истина`) и с проверкой источника. Не позволять пользователям выполнять произвольный код без ограничений — это прямой путь к взлому.

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/669.md)
См. также: №770

---

## №679 — Признак «Вызов сервера» у общих модулей

**Критичность:** 🔴 Блокирующее

**Суть:** Признак «Вызов сервера» на общем модуле открывает его экспортные функции для прямого вызова с клиента. Включать **только** для модулей, где это действительно нужно. Каждый такой модуль — точка атаки: все его экспортные функции должны валидировать параметры (№678).

📖 [Полный текст](https://github.com/zeegin/v8std/blob/main/docs/std/679.md)
См. также: №678

## Мини-чек-лист по безопасности

- [ ] Новый объект/поле — минимум в одной роли (№532)
- [ ] Операции в коде — с явной проверкой прав (№737)
- [ ] Привилегированный режим — только для служебных операций, с обоснованием (№485)
- [ ] Серверный API валидирует входные данные (№678)
- [ ] Нет `Выполнить`/`Вычислить` с пользовательским вводом (№770)
- [ ] Пароли/секреты — через защищённое хранилище (№740)
