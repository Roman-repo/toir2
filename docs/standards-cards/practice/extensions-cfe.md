# Практика: Паттерны расширений 1С (CFE)

> Практические шаблоны работы с конфигурациями расширений: типы перехватчиков, правила `ПродолжитьВызов`, маркеры изменений, ограничения заимствованных объектов.
> Адаптировано из [`extension-patterns.md`](https://github.com/comol/ai_rules_1c/blob/main/content/rules/extension-patterns.md) репозитория `ai_rules_1c`.

## Когда применять

При разработке расширений конфигурации (`**/Extensions/**/*.bsl`). ТОИР — типовая конфигурация, доработки обычно идут через расширения, поэтому паттерны особенно важны.

---

## Типы перехватчиков

| Директива | Тип | Когда использовать |
|---|---|---|
| `&Перед("ИмяМетода")` | Перед | Код перед оригинальным методом |
| `&После("ИмяМетода")` | После | Код после оригинального метода |
| `&ИзменениеИКонтроль("ИмяМетода")` | ИзменениеИКонтроль | Полная замена тела метода |

### Перед / После — простые перехватчики

```bsl
&НаСервере
&Перед("ПриЗаписи")
Процедура Расш1_ПриЗаписи()
    // Выполняется ДО оригинального ПриЗаписи
КонецПроцедуры

&НаСервере
&После("ПриЗаписи")
Процедура Расш1_ПослеЗаписи()
    // Выполняется ПОСЛЕ оригинального ПриЗаписи
КонецПроцедуры
```

### ИзменениеИКонтроль — полная замена

```bsl
&НаСервере
&ИзменениеИКонтроль("ОбработкаЗаполнения")
Процедура Расш1_ОбработкаЗаполнения(ДанныеЗаполнения, СтандартнаяОбработка)
    #Удаление
    // Оригинальный код (удалён)
    #КонецУдаления

    #Вставка
    // Новый код (добавлен)
    #КонецВставки

    ПродолжитьВызов();
КонецПроцедуры
```

---

## 🔴 Правила `ПродолжитьВызов()`

| Директива | `ПродолжитьВызов()` |
|---|---|
| `&Перед` | Вызывается автоматически **после**. **Не вызывать вручную.** |
| `После` | Оригинал уже выполнен. **Не используется.** |
| `&ИзменениеИКонтроль` | **Обязателен** — без него оригинальный метод **не выполнится**. |

Частый баг: забыли `ПродолжитьВызов()` в `&ИзменениеИКонтроль` → оригинальный метод молча не выполняется.

---

## Маркеры изменений (обязательны в `&ИзменениеИКонтроль`)

| Маркер | Назначение |
|---|---|
| `#Вставка` / `#КонецВставки` | Код, добавленный расширением |
| `#Удаление` / `#КонецУдаления` | Оригинальный код, который заменён |

Маркеры сохраняют семантику diff/merge при обновлении основной конфигурации и перезаимствовании расширения.

---

## 🟡 Префикс методов расширения

Имена процедур/функций, вводимых расширением — со **своим префиксом** (алиасом расширения):

❌ **Неправильно** (конфликт имён с другими расширениями):
```bsl
Процедура ДополнительнаяПроверка()
```

✅ **Правильно**:
```bsl
Процедура Расш1_ДополнительнаяПроверка()   // Расш1_ — алиас расширения
```

> **Важно:** префикс расширения (`Расш1_`, `МоеРасш_`) и префикс проекта (`торо_`) — **независимы**. Префикс проекта применяется к новым объектам/реквизитам метаданных; префикс расширения — к именам процедур/функций, чтобы избежать коллизий. Алиас **не должен** содержать букву `ё`.

---

## Ограничения заимствованных (adopted) объектов

- Заимствованный объект (`ObjectBelonging = Adopted`) — **не копия**, а ссылка на объект основной конфигурации. При обновлении основной конфигурации автоматически перечитывается.
- **Нельзя** удалять существующие реквизиты/табличные части заимствованного объекта — они принадлежат базе.
- **Можно** добавлять свои реквизиты/табличные части (с префиксом `{PREFIX}`).
- Модули заимствованных объектов — **только перехватчики** (`&Перед`/`&После`/`&ИзменениеИКонтроль`), без прямых правок тела процедур.
- Формы заимствованных объектов — можно добавлять элементы, **нельзя** удалять существующие.

## Антипаттерны

### 🔴 Прямая правка заимствованного модуля

```bsl
// НЕПРАВИЛЬНО: правка оригинального кода прямо в модуле
Процедура ПриЗаписи()
    // изменённый код...
КонецПроцедуры

// ПРАВИЛЬНО: перехватчик
&Перед("ПриЗаписи")
Процедура Расш1_ПриЗаписи()
    // дополнительный код
КонецПроцедуры
```

### 🔴 Забытый `ПродолжитьВызов`

```bsl
// ОПАСНО: оригинальный метод не выполнится!
&ИзменениеИКонтроль("ОбработкаПроведения")
Процедура Расш1_ОбработкаПроведения(Отказ)
    // свой код...
    // ЗАБЫЛИ: ПродолжитьВызов();
КонецПроцедуры
```

## 🟢 Назначение расширения

В свойствах расширения укажите `Назначение`:

| Тип | Назначение | Когда использовать |
|---|---|---|
| Patch | `Patch` | Минимальные изменения, только перехватчики |
| Customization | `Customization` | Реквизиты, формы, модули |
| AddOn | `AddOn` | Полностью новая функциональность |

Значение влияет на поведение при обновлении и способ повторного применения расширения.

---

## Чек-лист ревью расширения

- [ ] `&ИзменениеИКонтроль` содержит `ПродолжитьВызов()` (кроме случаев полной замены)
- [ ] Используются маркеры `#Вставка`/`#Удаление`
- [ ] Имена процедур — с префиксом алиаса расширения
- [ ] Нет прямых правок оригинального кода в заимствованных модулях
- [ ] Не удаляются существующие элементы заимствованных объектов
- [ ] Указано назначение расширения (Patch/Customization/AddOn)
- [ ] Префикс расширения не содержит буквы `ё`
