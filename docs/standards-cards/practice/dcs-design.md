# Практика: Проектирование отчётов СКД

> Правила проектирования отчётов на Системе Компоновки Данных (СКД / DCS): наборы данных, вычисляемые поля vs ресурсы, параметры, варианты, программный override.
> Адаптировано из [`dcs-design.md`](https://github.com/comol/ai_rules_1c/blob/main/content/rules/dcs-design.md) репозитория `ai_rules_1c`.

## Когда применять

При проектировании или ревью отчёта на СКД — до того, как писать схему компоновки или код `ПриКомпоновкеРезультата`.

---

## 1. Выбор типа набора данных

| Тип набора | Когда использовать |
|---|---|
| **Запрос** | По умолчанию. Данные уже в метаданных, и запрос выражает потребность. |
| **Объединение** | Комбинирование независимых запросов с одинаковой структурой колонок (движения + остатки). |
| **Объект** | Данные вычисляются в BSL (внешняя система, сложная агрегация, таблица строится процедурно) и предоставляются как `ТаблицаЗначений`. Использовать осторожно — теряется pushdown индексов и параметров. |

По умолчанию — **Запрос**. К **Объединению** переходить только при совпадении структуры. **Объект** — только когда запросом не обойтись.

📖 Стандарт: [№670](https://github.com/zeegin/v8std/blob/main/docs/std/670.md) Содержание отчёта

---

## 2. Вычисляемое поле vs Ресурс vs Поле запроса

Три разных механизма — выбор по **моменту материализации значения**, а не по «удобству набора».

| Механизм | Когда вычисляется | Для чего |
|---|---|---|
| **Поле запроса** | Один раз, при выполнении запроса на СУБД | Всё, что СУБД может вычислить — предпочтительно для любой логики, кроме presentation-only и aggregation-only |
| **Ресурс** | При агрегации, на итогах движка | Количества, которые надо суммировать/усреднять/считать по группировкам. Участвуют в итогах. |
| **Вычисляемое поле** | По каждой строке, после получения строки запросом | Построчные производные (представление, конкатенация, приведения типов, простая арифметика на существующих полях). В итогах не участвуют, кроме как через `Вычислить()`. |

Порядок предпочтения: **поле запроса → ресурс → вычисляемое поле**. Проталкивание вычислений в запрос уменьшает объём строк, которые движок гонит клиенту.

🔴 **Антипаттерн:** агрегация в `Вычисляемое поле` через `Вычислить("Сумма(...)", …)` — теряется использование индексов и форсируется полный скан строк. Используйте **Ресурс**.

## 3. Параметры

- **`Параметр` vs `ПараметрВыбора`.** `Параметр` привязан к запросу/набору данных; `ПараметрВыбора` — UI-фильтр. Не взаимозаменяемы. `Параметр` — для входов запроса (`&Период`); `ПараметрВыбора` — для ограничения выбора пользователя в поле.
- **Параметры периодов** для виртуальных таблиц (`Остатки(&Период, …)`, `ОстаткиИОбороты(&НачалоПериода, &КонецПериода, …)`) — **всегда** через параметры, никогда литералами дат в тексте запроса.
- **Флаг `Доступен`** — `Ложь` для параметров, вычисляемых программно (текущий пользователь, текущая дата) и недоступных пользователю.
- **`Использование`** — `ВсегдаИспользовать` только для параметров, которые не могут быть пустыми; иначе `Авто`, чтобы движок мог исключить неиспользуемые параметры из плана.

📖 Стандарт: [№407](https://github.com/zeegin/v8std/blob/main/docs/std/407.md) Параметры отчёта в СКД

## 4. Варианты и настройки

- **Варианты** — это *разные формы отчёта*, а не пользовательские фильтры. Использовать для разделения принципиально разных представлений одного отчёта («по документам» vs «по контрагентам»). Добавлять вариант «тот же отчёт с другим фильтром по умолчанию» — **неправильно**, для этого есть пользовательские настройки.
- **Пользовательские настройки** (`Настройки пользователя`) — держать набор минимальным. Каждая настройка — контракт поддержки. Сокращайте поверхность:
  - всё, что **не** должно быть пользовательским регулятором — помечать `Недоступен`;
  - `БыстрыеНастройки` для 3–5 полей, которые пользователь реально меняет;
  - `Авто` по умолчанию вместо пустых значений для `Период`, `Организация`.

## 5. Программный override компоновки

Для нетривиальных отчётов канонический паттерн — **программный override компоновки**, а не редактирование схемы под каждый вариант. Точки hook'а в порядке приоритета:

1. **`ПриКомпоновкеРезультата`** (модуль объекта отчёта) — предпочтительно. Модификация компоновки до/после стандартного компоновщика.
2. **`ПриЗагрузкеПользовательскихНастроекНаСервере` / `ПриЗагрузкеНастроекНаСервере`** — программная инъекция настроек (фильтры, параметры) при загрузке формы.
3. **`КомпоновщикНастроек.Настройки`** — прямая манипуляция деревом настроек.

### Шаблон программной инъекции фильтра

```bsl
Процедура ПриКомпоновкеРезультата(ДокументРезультат, ПараметрыВывода, СтандартнаяОбработка)

    // Результат формируем сами; платформа НЕ должна запускать дефолтную компоновку.
    СтандартнаяОбработка = Ложь;

    КомпоновщикНастроек.ЗагрузитьНастройки(СхемаКомпоновкиДанных.НастройкиПоУмолчанию);
    УстановитьПараметр("Период",       ПериодОтчета);
    УстановитьФильтр("Организация",    Организация);

    Попытка

        МакетКомпоновки = Новый КомпоновщикМакетаКомпоновкиДанных().Выполнить(
            СхемаКомпоновкиДанных, КомпоновщикНастроек.Настройки, , ,
            Тип("ГенераторМакетаКомпоновкиДанных"));

        ПроцессорКомпоновки = Новый ПроцессорКомпоновкиДанных;
        ПроцессорКомпоновки.Инициализировать(МакетКомпоновки);

        ПроцессорВывода = Новый ПроцессорВыводаРезультатаКомпоновкиДанныхВТабличныйДокумент;
        ПроцессорВывода.УстановитьДокумент(ДокументРезультат);
        ПроцессорВывода.Вывести(ПроцессорКомпоновки);

    Исключение

        ДанныеОшибки = Новый Структура;
        ДанныеОшибки.Вставить("Отчет",     Метаданные().Имя);
        ДанныеОшибки.Вставить("Период",    ПериодОтчета);
        ДанныеОшибки.Вставить("Подробно",  ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));

        ЗаписьЖурналаРегистрации(
            "Отчет." + Метаданные().Имя + ".Ошибка",
            УровеньЖурналаРегистрации.Ошибка,
            Метаданные(), ,
            НСтр("ru = 'Не удалось сформировать отчет.'"),
            ДанныеОшибки);

        ВызватьИсключение;

    КонецПопытки;

КонецПроцедуры
```

**Важные нюансы шаблона:**
- `СтандартнаяОбработка = Ложь` устанавливается **до** `Попытка` — если обработчик выйдет через `ВызватьИсключение` в середине рендера, платформа не должна молча откатиться к дефолтной компоновке и выдать второй «полуиспечённый» документ.
- Логирование по канонам журналирования: имя события через точку (`Отчет.<Имя>.Ошибка`), структурированные `Данные = Структура`, `ПодробноеПредставлениеОшибки` (не `КраткоеПредставлениеОшибки`), re-raise.
- `УстановитьПараметр` и `УстановитьФильтр` — локальные помощники; выносите их в модуль менеджера отчёта, чтобы override оставался компактным.

## 6. Взаимодействие с RLS

- Запросы СКД по умолчанию выполняются под ролями пользователя; применяются все `ОграничениеДоступа` задействованных объектов метаданных.
- Если отчёт намеренно требует полной видимости (регуляторные отчёты для бухучёта/зарплаты) — оборачивайте компоновку в `УстановитьПривилегированныйРежим(Истина)` **только** в `ПриКомпоновкеРезультата`, и всегда парно с `УстановитьПривилегированныйРежим(Ложь)` в `Попытка`/`КонецПопытки`. Зафиксируйте причину в комментарии.
- Не расширяйте видимость молча — каждое использование привилегированного режима должно быть обосновано.

📖 Стандарт: [№485](https://github.com/zeegin/v8std/blob/main/docs/std/485.md) Привилегированный режим

## 7. Чек-лист производительности СКД

- [ ] Поля фильтров индексированы — каждый параметр в `ГДЕ` попадает в индекс
- [ ] Виртуальные таблицы фильтруются через параметры (`Остатки(&Период, Условие)`), не через `ГДЕ` после вызова
- [ ] `ПЕРВЫЕ N` для пагинируемых/«топ-N» отчётов — лимит в запрос, не в hook форматирования
- [ ] Нет `ВЫРАЗИТЬ` в левой части `ГДЕ` — disables индекс
- [ ] Наборы данных типа **Объект** с большими `ТаблицаЗначений` — главный источник торможения; рассмотрите материализацию во временный регистр сведений
- [ ] Агрегаты накопления включены там, где ускоряют

---

## Чек-лист ревью СКД

- [ ] Тип набора данных — Запрос (не Объект без необходимости)
- [ ] Вычисления протолкнуты в запрос/ресурс, не в вычисляемое поле
- [ ] Параметры периодов ВТ — через параметры, не литералами
- [ ] Минимум пользовательских настроек, неиспользуемые — `Недоступен`
- [ ] Программный override через `ПриКомпоновкеРезультата` с `СтандартнаяОбработка = Ложь` ДО `Попытка`
- [ ] Привилегированный режим — парный (Истина/Ложь) и обоснован
