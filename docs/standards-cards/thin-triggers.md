# Тонкие триггеры — чек-лист самопроверки

> Короткий набор признаков в коде, которые **легко проскочить «по памяти»**.
> Проходить по этому списку **после написания кода**, построчно.

Это **не** правила — это *симптомы*, на которые надо обратить внимание и открыть соответствующую карточку. Список компактный намеренно: проверка должна занимать секунды, а не минуты.

## Как пользоваться

После написания/правки кода — прогоните по этому чек-листу. Для каждого найденного триггера — откройте указанную карточку и сверьтесь.

## 🔴 Галлюцинации и соответствие API (критические триггеры)

> Этот класс ошибок **не ловится другими чек-листами**. Он про случаи, когда ИИ использует конструкцию, которая **звучит правдоподобно, но не существует** или недоступна в версии платформы проекта. **Триггеры метаданных (UUID, области) перенесены в секцию «Метаданные и XML» выше.**

| Триггер / ситуация | Что проверить | Как |
|---|---|---|
| Использую функцию, которая **не является 100% стандартной** платформенной (`Справочники.X.НайтиПоКоду`, `СтрНайти`, `СтрСоединить` и т.п.) | Существует ли она реально? Не выдумал ли? | `grep -rn "Функция <Имя>" Project/Toir/src --include=*.bsl` — есть ли определение в проекте? |
| Имя функции звучит «по-1С-овски» (`НайтиИлиСоздать`, `ПолучитьСсылкуЭлемента`, `СоздатьНоменклатуру`) | Это типичный паттерн **галлюцинации** — звучит правдоподобно, но не существует | Проверить `grep`'ом в проекте; если нет — либо определить, либо раскрыть через стандартные средства |
| Использую метод платформы, появившийся в новой версии (`ДокументМикс`, нативный парсер `.xlsx`, `Асинх`/`Ждать`) | Доступен ли в версии проекта? | Проверить `compatibilityMode` в `Configuration.mdo`; сверить с версией появления метода |
| Ссылаюсь на метод БСП (`ОбщегоНазначения.ИмяМетода`) | Реально ли он есть в версии БСП проекта? | `grep -rn "Функция <Имя>" Project/Toir/src/CommonModules --include=*.bsl` |
| Использую метод/свойство, «помню которое» из обучающих данных | Это может быть устаревшим или из другой версии | При сомнении — проверить `grep`'ом по проекту и фиксировать версию |
| Ввожу «обёрточную» функцию без её определения | Раскрыть явно, через какие платформенные средства она реализуется | Либо определить тело, либо убрать псевдовызов |
| 🔴 Создаю метаданные и использую «удобный» UUID (`a1b2c3d4…`) | Это плейсхолдер, не настоящий UUID | См. секцию «Метаданные и XML» выше; генерировать случайно |

**Красные флаги галлюцинации** (имена, которые ИИ склонен выдумывать):
- `НайтиИлиСоздать...`, `ПолучитьИлиСоздать...`
- `СоздатьНоменклатуру`, `ЗаполнитьИзСтроки` (звучит как метод БСП, но часто выдумка)
- `ОбщегоНазначения.СоздатьЭлемент` (нет такого в БСП)
- `ЗагрузитьТабличныйДокумент` (нет такого метода платформы)

## Как встроен в процесс

Этот чек-лист — **фаза самопроверки** в процедуре работы над задачей (см. [AGENTS.md → Порядок работы](../../AGENTS.md)). Прогоняется после написания кода, перед коммитом/передачей на ревью.

Архитектурные вопросы (до кода) — в [arch-checklist.md](./arch-checklist.md).
