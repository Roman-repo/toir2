# Архитектурный чек-лист — вопросы эксперта до написания кода

> Вопросы, которые **сеньор задаёт себе перед задачей**, а не после.
> Цель: поднять мышление с «как написать» на «где, зачем и каковы последствия».
> Проходится **до** написания кода — на этапе планирования.

## Как пользоваться

После локализации объектов (этап 1 процедуры в `AGENTS.md`), **до** написания первой строки — прогоните по этому чек-листу. Для каждого «нет/не уверен» — остановитесь и переосмыслите.

---

## 1. Где будет жить логика?

| Вопрос | Если ответ «в форме» | Эксперт делает |
|---|---|---|
| Бизнес-логика (расчёт, проведение, проверки)? | ❌ | Общий модуль (`торо_...Сервер`) или модуль объекта |
| Обращение к данным ИБ? | ❌ | Только на сервере |
| UI-логика (видимость, доступность)? | ✅ допустимо в форме | Через условное оформление, не кодом |
| Переиспользуемая операция? | ❌ | Общий модуль, не копия в форме |

**Правило:** форма — только UI и вызовы сервера. Бизнес-логика и данные — на сервере в общих модулях.

📖 [forms.md №629](./forms.md) · [patterns.md → Separation of Concerns](./patterns.md)

## 2. Есть ли уже готовое? (чек переиспользования)

**Прежде чем писать функцию — проверьте, нет ли её уже в проекте:**

```bash
# поиск по прикладному коду
grep -rn "Функция.*Получить" Project/Toir/src/CommonModules --include=*.bsl | grep торо_

# поиск в БСП (без префикса — чужой код)
grep -rn "Функция.*Получить" Project/Toir/src/CommonModules --include=*.bsl | grep -v "торо_\|гкс_"
```

Что проверять:
- **БСП** — `ОбщегоНазначения.*`, `ОбщегоНазначенияКлиентСервер.*`, `Пользователи.*`, `РаботаСФайлами.*` — типовые операции уже реализованы.
- **Прикладные общие модули ТОИР** — `торо_Ремонты`, `торо_ПланированиеРемонтов`, `торо_РаботаСНаработкой` — не дублируйте.
- **Модули менеджеров** — у документов/справочников есть модули менеджеров с общими операциями.

🔴 **Антипаттерн:** написать свою `ПолучитьРеквизит()`, когда есть `ОбщегоНазначения.ЗначенияРеквизитовОбъекта()`.

## 3. Кто зависит от изменяемого объекта? (impact-анализ)

Перед правкой существующего объекта:

```bash
# кто ссылается на объект/функцию
grep -rn "торо_ИмяОбъекта" Project/Toir/src --include=*.bsl
grep -rn "ИмяФункции" Project/Toir/src --include=*.bsl
```

| Вопрос | Действие |
|---|---|
| Меняю экспортную функцию общего модуля? | Проверить всех вызывающих — не сломается ли сигнатура |
| Меняю реквизит объекта? | Проверить запросы/отчёты, где он используется |
| Меняю проведение документа? | Проверить подписки на события, связанные документы |
| Меняю структуру регистра? | Проверить все запросы к ВТ этого регистра |

📖 Карта движений: [`03_Документы_и_движения.md`](../architecture/03_Документы_и_движения.md) — кто куда пишет.

## 4. Что пройдёт через клиент-сервер?

| Вопрос | Если ответ «много» |
|---|---|
| Сколько данных я перегоню за один вызов? | Сократить до нужных полей, не «объект целиком» |
| Сколько серверных вызовов в одной операции? | Сгруппировать в один |
| Можно ли обойтись `НаСервереБезКонтекста`? | Если форма не нужна — да |

**Правило:** каждый round-trip дорог. Группируйте; не делайте по вызову на каждое поле.

📖 [performance.md №487, №636](./performance.md)

## 5. Что произойдёт при ошибке/отмене?

| Вопрос | Эксперт предусматривает |
|---|---|
| Что если пользователь прервёт операцию? | Транзакция откатится; partial state не останется |
| Что если внешний сервис недоступен? | Таймаут, fallback, сообщение пользователю |
| Что если данные некорректны? | Валидация до записи, понятное сообщение |
| Что если два пользователя одновременно? | Блокировка перед read-modify-write |

**Правило:** любое проведение/запись — продумать путь отказа. «Счастливый путь» — это половина кода.

📖 [practice/locks-transactions.md](./practice/locks-transactions.md) · [integration.md №748](./integration.md)

## 6. Производительность «по умолчанию»

| Вопрос | Если «нет» |
|---|---|
| Каждое условие `ГДЕ` попадает в индекс? | Переписать или добавить индекс |
| Читаю одно и то же значение повторно? | Закэшировать в переменную |
| В цикле — обращение через точку к ссылке? | Вынести чтение до цикла |
| Объём данных grows с базой? | Пагинация / `ПЕРВЫЕ N` / пакетная обработка |
| Автообновление динамического списка? | Только если реально нужно; период не короткий |

**Правило:** производительность — не «потом оптимизирую», а «сразу пишу эффективно».

📖 [performance.md](./performance.md) · [queries.md №658, №652](./queries.md)

## 7. Читаемость и сопровождаемость

| Вопрос | Если «нет» |
|---|---|
| Процедура длиннее 50 строк? | Декомпозировать |
| Есть магические числа (кроме 0, 1)? | Константа или комментарий |
| Имя функции отражает действие? | Переименовать |
| Сложное условие без комментария? | Добавить «// почему так» |
| Закомментированный код? | Удалить (git помнит) |

**Правило:** код пишется один раз, читается сотни. Оптимизируйте для читателя.

## Краткая шпаргалка (printed in memory)

```
ГДЕ ЛОГИКА?     → форма = UI, сервер = данные/логика
УЖЕ ЕСТЬ?       → grep по БСП и торо_ перед написанием
КТО ЗАВИСИТ?    → impact-анализ перед правкой
ЧТО ЧЕРЕЗ СЕТЬ? → минимум round-trips и данных
ЧТО ПРИ ОТКАЗЕ? → таймаут, блокировка, откат
ИНДЕКС?         → каждое ГДЕ попадает в индекс
ЧИТАЕМО?        → < 50 строк, без магических чисел, «почему» в комментариях
```
