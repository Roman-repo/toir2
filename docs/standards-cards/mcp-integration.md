# Интеграция с v8std через MCP

> Документация по [MCP-серверу v8std](https://github.com/zeegin/v8std/blob/main/docs/mcp.md).
> Это **альтернативный путь** к карточкам: вместо загрузки каталога в контекст ИИ — точечные запросы к живой базе стандартов.

## Что такое MCP v8std

**Model Context Protocol (MCP)** — протокол, через который ИИ-помощник может сам обращаться к внешнему источнику. MCP v8std даёт ИИ доступ к актуальной базе стандартов [v8std.ru](https://v8std.ru): поиск, полные тексты, связи, объяснение диагностик.

**Сервис не меняет код и не запускает проверки.** Он только возвращает материалы: стандарты, описания диагностик и связи между ними.

## Зачем это нужно

ИИ-помощник без источника может ошибиться в правилах 1С или сослаться на несуществующий стандарт. MCP даёт ему доступ к актуальной базе. Помощник:

- найдёт стандарт по номеру, коду диагностики или обычной фразе;
- получит полный текст стандарта;
- объяснит предупреждение АПК / BSL LS / EDT;
- подберёт стандарты по фрагменту кода;
- перейдёт от диагностики к пункту стандарта.

## Карточки vs MCP — когда что

| Подход | Когда лучше |
|---|---|
| **Карточки** (`docs/standards-cards/`) | Автономная работа, офлайн, предсказуемый контекст, нет внешних запросов |
| **MCP** | Нужен самый свежий текст стандарта; спорный случай; объяснение конкретной диагностики; большой фрагмент кода |

Карточки и MCP **не исключают друг друга** — карточки дают базовый контекст всегда, MCP подключается для точечных запросов.

## Доступные методы MCP

| Метод | Назначение | Пример запроса |
|---|---|---|
| `v8std_search` | Поиск по фразе/номеру/коду диагностики | `модальные окна`, `std437`, `bslls:UsingModalWindows` |
| `v8std_get_page` | Полный текст найденной страницы | — |
| `v8std_get_related` | Связанные страницы (стандарт ↔ диагностика) | — |
| `v8std_explain_snippet` | Подбор стандартов по фрагменту кода | небольшой блок BSL |
| `v8std_explain_diagnostics` | Объяснение списка диагностик АПК/BSL LS/EDT | после проверки проекта |

## Варианты подключения

### 1. Публичный сервис (быстро, без ключа)

```text
https://ai.v8std.ru/mcp
```

⚠️ **Публичный MCP видит текст запросов.** Не передавайте закрытый код. Для коммерческих данных — локальный запуск.

**Примеры конфигурации:**

Cursor (`.cursor/mcp.json`):
```json
{
  "mcpServers": {
    "v8std": { "url": "https://ai.v8std.ru/mcp" }
  }
}
```

Claude Code:
```bash
claude mcp add --transport http v8std https://ai.v8std.ru/mcp
```

### 2. Локальный запуск (для закрытого кода)

В репозитории v8std есть готовый docker-compose:

```bash
git clone https://github.com/zeegin/v8std
cd v8std
docker compose -f docker-compose/docker-compose.yml up -d v8std-mcp
```

MCP-сервер будет доступен на `http://127.0.0.1:8765/mcp` и читает локальный индекс `docs/ai/pages.jsonl` из смонтированного репозитория.

```bash
claude mcp add v8std-local --url http://127.0.0.1:8765/mcp
```

Преимущества локального запуска:
- полный офлайн/автономия;
- приватность — код не покидает машину;
- возможность править индекс под свои нужды.

## Примеры вопросов к ИИ после подключения

- «Найди стандарт про модальные окна в 1С».
- «Объясни диагностику `bslls:UsingModalWindows`».
- «Что означает `acc:1245` и какой стандарт с ним связан?»
- «По этому фрагменту кода подбери применимые стандарты v8std».
- «Какие стандарты относятся к локализации интерфейсных текстов?»
