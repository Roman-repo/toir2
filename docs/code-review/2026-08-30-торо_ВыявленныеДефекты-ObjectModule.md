## Детали замечаний

### 🔴 №1 — Чтение БД и запись статусов оснований внутри транзакции проведения

**Код (косяк):**

```bsl
// ObjectModule.bsl:162–171, ОбработкаПроведения — выполняется В ТРАНЗАКЦИИ записи
	Если НЕ Отказ Тогда
		УстановитьУправляемыеБлокировки();
	КонецЕсли;

	ТаблицаВО = СформироватьТаблицуВнешнихОснований();                     // :166 ← запрос к БД
	ДвиженияПоРегистру_торо_ВнешниеОснованияДляРабот(РежимПроведения, ТаблицаВО, Отказ);

	Движения.торо_СтатусыДокументовВыявленныхДефектов.Записывать = Истина;
	торо_РаботаСоСтатусамиДокументовСервер.УстановитьСтатусДокумента(      // запись движений
		Ссылка, Ссылка, Движения, Перечисления.торо_СтатусыДокументов.Зарегистрирован);
	торо_РаботаСоСтатусамиДокументовСервер.ИзменитьСтатусыДокументовОснований(Ссылка);  // :171 ← пакет
	                                                                        // запросов + записи
	                                                                        // ДРУГИХ документов
```

`СформироватьТаблицуВнешнихОснований` (:212–267) выполняет пакетный запрос к
РС `торо_ВнешниеОснованияДляРабот`; `ИзменитьСтатусыДокументовОснований`
(проверено: `CommonModules/торо_РаботаСоСтатусамиДокументовСервер/Module.bsl:95`)
строит серию запросов и меняет статусы документов-оснований.

**Почему косяк:** стандарт №783 — транзакция короткая, только запись; чтение
данных — вне транзакции. Здесь транзакция проведения захватывает чтение чужих
записей регистра и каскадную запись других документов: блокировки держатся
дольше, растёт вероятность взаимоблокировок и время проведения под
нагрузкой; откат любой части каскада откатывает всё.

**Как исправить (направление):** данные для `ТаблицаВО` готовить до начала
записи (серверный вызов из формы до `Записать()`; программная запись — до
`НачатьТранзакцию`), в проведении — только потреблять подготовленное.
Каскад `ИзменитьСтатусыДокументовОснований` вынести после фиксации транзакции
(подписка на событие после записи / отложенное применение). Если полный
вынос невозможен из-за согласованности статусов — зафиксировать компромисс
обоснованием в 05a и максимально сузить объём читаемого.

### 🔴 №2 — Обработчики записи без проверки ОбменДанными.Загрузка

**Код (косяк):**

```bsl
// ObjectModule.bsl:85–93
Процедура ПередЗаписью(Отказ, РежимЗаписи, РежимПроведения)
	
	Для Каждого Дефект Из СписокДефектов Цикл          // ← генерация ID отработает и при загрузке обмена
		Если Не ЗначениеЗаполнено(Дефект.ID) Тогда
			Дефект.ID = Новый УникальныйИдентификатор;
		КонецЕсли;
	КонецЦикла;
	
КонецПроцедуры
```

То же — `ОбработкаПроведения` (:119): движения и смена статусов отработают
при загрузке данных обменом.

**Почему косяк:** правило каталога `DataExchangeLoad`. При загрузке данных
(обмен, КД, миграции) бизнес-логика записи должна отключаться: повторная
генерация ID и статусов рас-sync'ает документ с источником обмена (данные
пришли уже провалидированными).

**Как исправить:**

```bsl
Процедура ПередЗаписью(Отказ, РежимЗаписи, РежимПроведения)
	Если ОбменДанными.Загрузка Тогда
		Возврат;
	КонецЕсли;
	// …существующая логика
КонецПроцедуры
```

Аналогичную проверку добавить в начало `ОбработкаПроведения` (при загрузке —
проведение обычно снимается/не выполняется; согласовать с механикой
конкретного обмена).

### 🔴 №3 — Когнитивная сложность ОбработкаЗаполнения

**Код (косяк):**

```bsl
// ObjectModule.bsl:13–79 — 4 ветки ТипЗнч, в трёх дублируется блок:
	ДатаОбнаружения     = Основание.Дата;
	Инициатор           = Основание.Ответственный;
	Организация         = Основание.Организация;
	Подразделение       = Основание.Подразделение;
	ДокументыОснования.Добавить().ДокументОснование = Основание;
	// …специфика ветки: Комиссия / ДокументОснование / ДефектВыявленВПроцессе
```

**Почему косяк:** `MethodCognitiveComplexity` (каталог checkbsl): метод из
четырёх почти одинаковых веток не удерживается в голове; изменение общего
набора полей требует синхронной правки в 4 местах — типичный источник
расползания багов.

**Как исправить:** декомпозиция — общий блок в помощник, ветки — только
специфика:

```bsl
Процедура ОбработкаЗаполнения(Основание)
	Если ЗаполнитьПоДокументуОснованию(Основание) Тогда
		// ветка вернула Истина — специфика уже внутри помощника:
		Если ТипЗнч(Основание) = Тип("ДокументСсылка.торо_ВнешнееОснованиеДляРабот") Тогда
			Комиссия = Основание.Комиссия;
		ИначеЕсли ТипЗнч(Основание) = Тип("ДокументСсылка.торо_УчетКонтролируемыхПоказателей") Тогда
			ДокументОснование = Основание.Ссылка;
		КонецЕсли;
	ИначеЕсли ТипЗнч(Основание) = Тип("Структура") Тогда
		ЗаполнитьПоСтруктуреПараметров(Основание);   // :52–79 без изменений
	КонецЕсли;
	
	ЗаполнитьРеквизитыШапкиПоУмолчанию();
КонецПроцедуры
```

### 🟡 №4 — Точечные чтения реквизитов одной ссылки через точку

**Код (косяк):**

```bsl
// ObjectModule.bsl:15–22 (повторено в ветках :24–30, :32–40, :42–50)
	ДатаОбнаружения = Основание.Дата;          // неявный запрос к БД
	Инициатор = Основание.Ответственный;       // ещё один
	Организация = Основание.Организация;       // ещё один
	Подразделение = Основание.Подразделение;   // ещё один
	ДокументыОснования.Добавить().ДокументОснование = Основание;
	Комиссия = Основание.Комиссия;             // только в первой ветке
```

**Почему косяк:** каждое обращение `Ссылка.Реквизит` — отдельный неявный
запрос; суммарно ~18 чтений одного и того же объекта по 4 веткам. Стандарт
№648 (точечное чтение ровно нужных полей) и №496 (групповое чтение через БСП).

**Как исправить:**

```bsl
	РеквизитыОснования = ОбщегоНазначения.ЗначенияРеквизитовОбъекта(Основание,
		"Дата, Ответственный, Организация, Подразделение");
	ДатаОбнаружения = РеквизитыОснования.Дата;
	Инициатор       = РеквизитыОснования.Ответственный;
	Организация     = РеквизитыОснования.Организация;
	Подразделение   = РеквизитыОснования.Подразделение;
	// «Комиссия» — реквизит только ВнешнеОснования: читать в спец-ветке
```

Естественно встаёт в помощник из замечания №3.

### 🟡 №5 — ТекущаяДата() на границе суток

**Код (косяк):**

```bsl
// ObjectModule.bsl:299 и :308
	ДатаОбнаружения = ТекущаяДата();
	…
	ЭтотОбъект.Дата = ТекущаяДата();
```

**Почему косяк:** `ForbiddenMethodCurrentDate`: `ТекущаяДата()` — время
сервера без сеансной таймзоны; при несовпадении часовых поясов дата
обнаружения дефекта и дата документа могут «прыгнуть» на соседние сутки.

**Как исправить:** `ТекущаяДатаСеанса()` в обоих местах.

### 🟡 №6 — Экспортные переменные как канал межмодульного состояния

**Код (косяк):**

```bsl
// ObjectModule.bsl:7–9
перем СтруктураДанных Экспорт;  // заполняется снаружи (статусная модель)
Перем БезусловнаяЗапись Экспорт; // ставится снаружи (торо_ОбновлениеИБ:2689 и др.)
```

**Почему косяк:** `ExportVariable` — скрытое глобальное состояние: модули
сцепляются через переменную, поведение записи зависит от того, кто и когда
её выставил (в фоновых заданиях и параллельных вызовах — источник
трудновоспроизводимых эффектов). Нюанс: паттерн единый для всех документов
ТОИР (проверено по торо_ЗаявкаНаРемонт, торо_ЗакрытиеЗаявокИРемонтов) —
точечная правка только здесь ломает единообразие.

**Как исправить:** на уровне нового кода — методы вместо переменных
(геттер/сеттер или параметры). Для существующего типового блока —
зафиксировать как осознанный паттерн поставщика в 05a (обоснование), не
править точечно.

### 🟡 №7 — Сообщения проверки без привязки к полю

**Код (косяк):**

```bsl
// ObjectModule.bsl:102–113, ОбработкаПроверкиЗаполнения
	Если ТекСтрокаСписокДефектов.ОбъектРемонта.Пустая() Тогда
		ТекстСообщения = НСтр("…ru='Не указан объект ремонта'…");
		ОбщегоНазначения.СообщитьПользователю(ТекстСообщения,,,,Отказ);   // ← без поля
	КонецЕсли;
```

**Почему косяк:** №400: пользователь видит «Не указан объект ремонта», но не
видит, в какой из строк ТЧ «Список дефектов» искать; при десятках строк
сообщение бесполезно.

**Как исправить:** привязка к полю и строке — у БСП-обёртки для этого есть
параметры (имя реквизита + путь к данным строки):

```bsl
	ОбщегоНазначения.СообщитьПользователю(ТекстСообщения,,
		"ОбъектРемонта", "СписокДефектов[" + Формат(ИндексСтроки, "ЧГ=") + "]", Отказ);
```

(точную сигнатуру сверить с версией БСП конфигурации).

### 🟡 №8 — Битые es-строки НСтр

**Код (косяк):**

```bsl
// ObjectModule.bsl:105
ТекстСообщения = НСтр("es='de la reparación';ru='Не указан объект ремонта';en='Repair object not specified'");
// ObjectModule.bsl:110
ШаблонСообщения = НСтр("es='2.';ru='Не указан вид дефекта %1/%2.';en='The type of defect%1 /%2 is not specified.'");
```

**Почему косяк:** №761/№765: если у пользователя испанский язык интерфейса,
вместо сообщения он увидит обрывок «de la reparación» или «2.» — это хуже,
чем отсутствие перевода.

**Как исправить:** дописать корректный полный перевод
(es = 'No se ha especificado el objeto de reparación' /
'No se ha especificado el tipo de defecto %1/%2.') либо, если испанская
локаль не поддерживается, es-секции из строк убрать.

### 🟡 №9 — Подзапрос в ГДЕ при соединении + гигиена ВТ

**Код (косяк):**

```bsl
// ObjectModule.bsl:244–261, последний пакет запроса
	|ВЫБРАТЬ
	|	торо_ВнешниеОснованияДляРабот.ОбъектРемонта КАК ОбъектРемонта, …
	|ИЗ
	|	ВТ_ВнешниеОснованияИзОснований КАК ВТ_ВнешниеОснованияИзОснований
```
